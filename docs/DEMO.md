# Three-minute demonstration

1. Explain the idea: Catchy helps people recognize pressure and risky requests during conversations.
2. Open Demo studio and run the legitimate hospital example. Show that urgency alone does not trigger high risk.
3. Run the safe-account scam. Watch evidence build from claimed authority to pressure, secrecy and a secret-code request.
4. Point to exact evidence and the safe next action. Explain that severity is not a fraud probability.
5. Sign in and demonstrate a fresh typed caller statement against the real backend.
6. Show session history, optional retention and trusted-contact dialer links.
7. Explain the architecture, test results and limits. The evaluation includes known baseline failures, not just favorable examples.

Before presenting: install Python, run tests, verify localhost in the presentation browser, create a fictional account, warm any optional model and use fictional contacts. Keep guest demos available if the model service fails. Do not promise universal phone capture, automatic family alerts or validated clinical/financial outcomes.

Useful next differentiator: evaluate a held-out set of unseen scam scripts and legitimate calls, then measure false alerts and time to warning. Do not present the 12 development fixtures as real-world accuracy.
